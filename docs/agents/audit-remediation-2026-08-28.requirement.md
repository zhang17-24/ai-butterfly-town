# 审计修复迭代需求 · R1

> 来源：2026-08-28 投递前真实性审计  
> 产品基线：`docs/living-requirement-map.html` v1.5  
> 原则：优先修复会让面试官误判“功能是假实现”的缺口；不在本轮扩展室内、经济或完整 LLMOps。

## 1. 目标

把当前“栖溪镇可演示 + 生成世界可创建”的版本修成一条可信的双轨纵向切片：内置世界和动态生成世界都能在各自蓝图中移动、自主决策、接受事件并形成可追踪因果链；默认测试可稳定退出；长时间运行仍保持可解释状态。

## 2. 本轮需求

### R1-01 动态世界使用自身 Blueprint（P0）

- 服务端模拟、玩家移动、自动接近、事件空间传播必须读取目标世界持久化的 Blueprint。
- 动作目的地由地点能力标签解析，不得依赖 `cafe/clinic/riverside` 等栖溪镇固定坐标。
- 生成世界中的 NPC 和玩家位置必须始终落在本世界画布内的可行走区域。
- 内置栖溪镇无 `blueprint_json` 时继续使用预置 Blueprint，不产生回归。

验收：创建一个 360×300 的模板世界，推进模拟后所有角色坐标仍在画布内；玩家能移动并自动接近该世界居民。

### R1-02 玩家事件形成真实因果链（P0）

- NPC 决策读取到的已知事件必须保留事件 ID。
- 如果已知事件对最终候选动作产生了非零影响，生成的 `npc.action_started` 必须把相关事件 ID 写入 `causeIds`。
- 因果 API 应能返回 `玩家事件 → NPC 行动` 的边，页面可从行动反查事件。
- 不知情 NPC 的行动不得错误关联该事件。

验收：提交暴雨事件并推进模拟后，至少一个 NPC 行动带该事件 ID；因果图 `edges.length > 0`。

### R1-03 NPC 社交稳定性（P0）

- 随机源无论返回何值，居民配对不得出现无界循环。
- 同地空闲 NPC 可产生短对话事件；同一组不得选择同一个人为说话者和听者。
- 固定随机源测试必须在正常时间内退出。

验收：`npc-socialize.test.ts` 通过，完整 `pnpm verify` 能自然退出。

### R1-04 长时运行表达与状态约束（P1）

- 顶部日期由世界分钟计算，不再固定显示“周六”。
- 饥饿、精力、压力等达到极端阈值时，规则候选必须显著优先吃饭或休息，不能长期无视危险状态。
- UI 普通视图显示自然语言等级，同时保留数值用于解释。

验收：跨过 24 小时后日期发生变化；极端饥饿或低精力时对应生存动作是最高分候选。

## 3. 明确不在本轮实现

- 所有建筑室内、运行期扩建、经济与库存闭环；
- WORLD 真实结构模型和多模态 VISION 模型；
- AI 工作台真实重放/双模型对比；
- 世界包导入导出、线上额度、部署和视频。

这些项目保留在总需求中，但必须在交付文档中标为“后续/预留”，不能写成已完成。

## 4. Definition of Done

1. 新增或更新自动化测试覆盖四项需求；
2. `pnpm verify`、`pnpm test:e2e` 全部通过且进程自然退出；
3. Ego Lite 浏览器验证内置世界主流程与生成世界坐标；
4. 不覆盖现有未提交的 Seedream、视觉审查和气泡实现；
5. 完成后更新执行文档，记录真实完成项和仍保留的边界。
