AI 蝴蝶小镇

腾讯 AI 引擎部 · AI 全栈工程师面试项目｜先建立项目全貌，再通过持续对话逐层确定玩法、功能、数据与技术方案。
一句话定义
一个持续自主运转的日常生活 AI 小镇；玩家可以观察居民、与他们交谈，并向世界投入“事件种子”，观察个体差异如何逐步形成群体层面的连锁变化。

世界

已确定

接近现实日常生活的小型社会空间。地点、时间与公共状态持续变化，而不是一次性聊天场景。

日夜/时间地点公共事件可保存

居民 NPC

已确定

拥有明显不同的人设与属性，能感知当前状态，自主决定行动，并通过交流相互影响。

性格需求关系记忆行动

玩家

已确定

能力分三层：默认全局观察；作为一个居民 Agent 实例进入世界；并具备地图中的空间操控能力。

观察模式居民实例空间操控对话与行动

亮点扩展

自主生活是必须完成的基架；蝴蝶效应是其上的亮点能力，首版保留事件注入与影响追踪的扩展接口。

D01产品主次A“自主生活观察”是必须实现的基架；C“玩家作为居民参与”也是正式需求；B“蝴蝶效应”作为亮点扩展并预留入口。先证明小镇本身会生活，再证明玩家能进入，最后放大连锁影响。
D02玩家形态三种能力全部保留：默认全局观察、玩家作为居民 Agent 实例、玩家在地图中的空间操控。移动、触碰、寻路与交互距离留到地图阶段细化。
D03世界节奏默认持续实时运行；玩家不操作时，世界和居民也持续演化。不是点击“下一回合”才运行的回合制模拟器。
D04中途介入玩家可以在运行中移动、对话或插入世界事件；这些行为立即成为新的世界事实。相关居民必须在后续感知中读到变化并调整行为。
D05运行控制仅做暂停 / 继续；不做速度切换，也不做单步推进。暂停后世界时间与居民动作停止，继续后保持一致地恢复。
D06决策触发采用周期运行 + 事件触发：平时周期性自主生活，重要事件使相关居民提前决策。避免同一居民被周期和事件重复触发。
D07生活驱动采用日程基线 + 状态需求 + 事件响应。正常时有稳定生活轨迹，状态或事件变化时能合理偏离日程。
D08居民状态采用深度模型：稳定身份、动态身体与情绪、资源能力、社会关系、认知状态。包括性格偏好；实际展示的字段必须真正影响行为。
D09人格表达自然语言人设 + 数值性格特质 + 喜好、厌恶和价值观标签。真实 AI 与 Mock 降级共享同一个人物模型，并保持可辨识差异。
D10居民规模首版先完成 5 名完整 NPC，后续扩展到约 20 名。数据结构、界面与调度不能写死为只有 5 人。
D11运行精度约 20 名居民全部保持完整能力，不区分核心居民和低精度背景居民。每个人都有完整人格、状态、关系、记忆、规划、决策和对话。
D12AI 调度先按需判断是否需要重新规划；公共事件统一理解一次，再由相关居民独立决策并受控并发。共享事实一致，人格与记忆隔离；单个居民失败不拖垮整轮。
D13记忆基础短期事件 + 长期摘要 + 对每名居民的关系印象。旧经历要能持续影响后续行为，而不只是复述最近日志。
D14认知扩展记忆按近期性、重要性和情境相关性检索；高重要经历积累后形成简短反思。首版不要求复杂知识图谱或完整向量记忆平台。
D15规划层级长期目标 → 每日计划 → 当前具体动作；不同强度事件影响不同规划层。小事件不应轻易改变长期人生目标。
D16动作系统AI 开放推理，但最终必须调用可扩展动作工具；后端验证并执行真实状态变化。AI 与 Mock 共用动作注册表，禁止只用文字声称“已经行动”。
D17NPC 对话分级模拟：普通闲聊生成结果摘要；重要事件、冲突或秘密进行有限 2–4 轮交流。现场可展示完整对话；不在现场只显示摘要；双方形成各自主观记忆。
D18玩家身份创建一个新的独立玩家居民，并提供默认角色快速进入。与 NPC 共用居民数据模型，仅 controller 为 human。
D19观察切换全局观察只切换镜头；玩家居民留在原地，不消失，也不自动托管。切换视角不能改变位置、关系、状态和记忆。
D20地图移动采用点击地图寻路，玩家与 NPC 共用位置和路径系统。角色不能穿过障碍；可达目标必须稳定抵达。
D21接近交互远程可查看资料；执行现场动作时自动寻路接近 NPC，抵达合法距离后显示动作。处理目标移动和路径不可达，不允许远程执行现场行为。
D22玩家动作首版实现自由对话和至少 3 类情境动作；复用 NPC 动作工具。自然语言复合指令预留接口，不作为首版完整能力。
D23事件注入支持事件模板和自由文本；AI 先解析为结构化预览，玩家确认后才写入世界。不支持的部分必须明确标出，不能静默忽略。
D24信息可见性按事件类型传播；区分客观事实、居民掌握的信息和居民的主观理解。居民只能依据自己实际获得的信息决策，同一事件可形成不同版本。
D25蝴蝶效应首版实现带父事件和决策依据的因果链；平行世界只预留快照与分支标识。最终变化可以反向追踪到玩家事件或其他初始原因。
D26实时对话世界继续运行，但锁定对话参与者；紧急事件可以打断。其他居民持续生活，交谈双方不能同时执行冲突动作。
D27地图结构连续俯视室外地图与独立建筑室内场景同时需要。玩家和 NPC 使用统一跨场景导航，不以地点瞬移代替移动。
D28室内范围主要建筑全部可进入，不只制作一两个样板室内。不同建筑可复用生成模板，但每个实例有独立物品、入口和归属。
D29动态生成范围结构生成、AI 地图与角色美术、运行中继续扩建三层全部需要。此前“固定 7 类地点”的方案已撤回；世界内容由提示词和规则动态产生。
D30扩建发起玩家和 NPC 都能提出扩建；先生成提案预览，经玩家确认后写入世界，并可开启自动批准。每次扩建保留发起者、原因、预览、确认和生成结果。
D31地图生成结构蓝图与视觉识别结合：蓝图定义权威空间，图像模型生成美术，视觉模型识别后与蓝图校验。地图必须通过关键地点可达性与自动寻路测试。
D32审查失败严格以蓝图为准，自动重绘；超过重试上限后使用程序化基础素材。错误美术不能反向破坏碰撞、入口和连接逻辑。
D33视觉风格每个世界生成并锁定独立视觉规范，后续新增地图和角色必须复用。支持提示词和预设风格，但必须转化为清晰可玩的统一视角。
D34动态人口系统按世界规模、地点和职业建议人口，玩家生成前可修改；首版默认 5，目标约 20。人物作为完整社会关系群体生成，每个重要地点有人使用。
D35生活能力不用固定地点名称，而用能力标签校验进食、休息、工作、社交、安全、健康和公共信息传播。每项核心需求在任意世界中至少有一种合法满足方式。
D36地图扩张优先填充现有空地，必要时生成相邻新区；室内独立扩展。新旧区域道路连通、全局可达，原有世界状态不得被覆盖。
D37时间比例采用固定加速小镇时钟，暂定现实 2 秒等于小镇 1 分钟、一天约 48 分钟；比例可配置。运行中不提供速度切换，日程、动作和事件共用统一时钟。
D38跳过时间支持跳到当前动作结束和下一重要事件；后台快速但完整地执行期间模拟。紧急事件提前停止，结束后展示期间变化摘要。
D39状态表达后台保存 0–100 精确数值，普通 UI 显示分级自然语言，调试面板显示精确值。UI、AI 提示词与 Mock 规则使用一致的等级含义。
D40状态字段健康、饥饿、精力、心情、压力和社交需求为核心；世界可以生成扩展状态。扩展状态必须具备变化来源、消耗来源、阈值与行为影响。
D41多维关系有方向地记录熟悉度、好感、信任、尊重、关系标签和共同经历，并补充自然语言长期摘要。不同维度分别影响交流、秘密分享、合作和冲突等决策。
D42经济闭环工作收入、购买交换、真实库存、补货、物品消耗和转交构成轻量闭环。金钱与物品变化有来源和去向；动态价格与生产配方只预留字段。
D43动态动作稳定动作原语通过配置组合成世界专属动作，AI 不生成任意执行代码。每个动作都可校验、保存、回放并由 Mock 执行。
D44资源并发采用意图校验、到场后的短期预约与原子执行；失败或超时释放资源。禁止重复购买、负库存和多人占用唯一对象。
D45极端后果默认触发强制行为与能力限制；特定世界可配置昏迷、失业、破产或死亡等严重后果。居民不能无视危险状态继续普通日程；严重后果必须处理社会与资源影响。
D46模型角色完整实现世界编排、运行模拟、图像生成和视觉审查四类独立模型配置。更换或缺失某一模型角色时不影响其他模块；暂不做动态模型路由。
D47AI 与规则规则筛选合法候选，AI 结合人格、目标、记忆和关系选择，确定性执行器更新状态。AI 不能执行非法动作或直接任意修改数值。
D48结构化输出统一适配 Structured Output、Tool Calling 和普通 Chat JSON，经过 Schema、枚举和引用校验。无效输出修正一次，仍失败则降级；禁止部分写入世界。
D49上下文构建按行动、对话、计划、反思和生成任务构建最小相关上下文并设置独立 Token 预算。居民不能获得未感知的信息；开发者可查看本次实际上下文。
D50失败降级AI 超时或失败不阻塞世界；重试后使用相同动作 Schema 的规则 / Mock 决策器。请求携带决策 ID 与世界版本，迟到旧响应直接丢弃。
D51AI 检查器普通界面显示决策摘要，开发者面板展示输入、候选、输出、校验、降级、延迟、Token、成本和状态变化。任意一次行动都可解释；密钥和敏感配置永不展示。
D52主页面布局采用地图主导 + 可展开侧边面板；世界创建、完整因果分析和开发者检查器使用独立页面或大型覆盖层。关闭面板后可完整观察小镇，打开面板时地图仍保留足够区域。
D53创建页面一句话输入为主，可展开人口、风格、后果、审批、模式和随机种子等高级选项。展示真实分阶段生成进度；失败阶段可单独重试或降级。
D54NPC 面板默认摘要，进一步分为状态、计划、关系、记忆和决策；完整 AI 检查器独立进入。普通用户能快速理解当前行为，面试官能逐层验证系统。
D55事件与因果地图保留紧凑事件流，复杂事件进入含时间线、因果图和节点详情的大型分析视图。支持从最终结果反向追踪初始原因，并按居民、地点、类型和来源筛选。
D56对话界面NPC 闲聊显示地图短气泡；玩家和可见完整对话进入侧栏，不在现场只显示摘要。对话内容严格遵守玩家在场和知情规则。
D57事件入口观察工具栏打开事件编排侧栏，经模板 / 自由输入、AI 解析、地图高亮与确认后写入世界。确认前不得修改世界；提交后事件流立即出现起点。
D58应用首页提供继续上次世界、一句话创建、内置示例和完整世界库。面试官一次点击进入无密钥可玩世界，同时支持多个世界与生成任务管理。
D59设备范围桌面完整、平板主要功能、手机以观察、NPC、事件、对话和暂停为主，复杂工具简化或只读。手机分享链接可体验，但不要求复杂功能完全对等。
D60界面风格稳定的中性现代 UI，使用世界风格规范的少量主题色；普通面板生活化，开发者工具技术化。不同生成世界中保持清晰一致，同时让地图视觉主导体验。
D61持久化模型完整世界快照与不可变追加事件日志结合；恢复时加载最近快照并重放后续事件。兼顾恢复速度、完整历史、因果链、回放与分支。
D62自动保存每次有效变化立即写事件；周期、手动保存、事件注入、扩建和跳时等节点生成快照。任何已显示成功的动作都已持久化，快照生成不阻塞实时世界。
D63任务恢复按移动、AI、生成与原子执行等任务类型分类恢复，使用任务 ID、世界版本、阶段和结果引用保证幂等。重启后无重复调用、重复状态变化或半生成内容。
D64时间线分支从历史节点继续时自动创建新 branch_id，原时间线保持不变。分支共享过去并独立演化未来，任何分支均可单独恢复。
D65导入导出支持包含世界配置、状态、时间线、事件、规则、任务与资产清单的可移植世界包。另一台机器无原数据库也能导入继续；无密钥时可进入 Mock 模式。
D66存储清理滚动保留自动快照、长期保留里程碑、资产按哈希去重、删除分支后清理无引用内容。自动清理不得破坏仍可访问的时间线或共享资产。
D67无密钥体验同时提供验证过的内置世界与完整本地 Mock 管线，创建、模拟、对话、事件、因果和恢复均可体验。固定随机种子可复现，界面明确显示 AI 或 Mock 来源。
D68Mock 决策使用可解释效用评分，并用世界种子加入小幅、可复现的随机扰动。人格差异稳定，同一状态与种子产生相同结果。
D69Mock 对话本地解析意图与对象，检索角色已知记忆，结合人格、心情和关系生成模板回复并写入记忆。不能回答未知事实，无法理解时符合人设地请求澄清。
D70测试范围单元测试、确定性模拟与 API 集成测试、单条端到端主流程冒烟，同时覆盖关键故障注入。无网络、固定种子下稳定通过，主流程可一条命令运行。
D71真实 AI 测试默认测试全部离线；另提供手动或定时触发的四类模型契约测试。无 Key 可通过完整默认测试；真实测试只验证连接、Schema 和接口契约。
D72错误体验错误绑定具体对象并提供说明、重试、降级、取消、错误 ID 与开发者详情；世界尽可能继续运行。任何错误不导致 UI 永久加载，用户始终知道世界是否安全保存。
D73全栈语言前端 React + Phaser，后端 Node.js / TypeScript，并共享 Schema 与类型。减少上下文切换，前后端契约可复用，便于面试现场修改。
D74渲染边界Phaser 负责世界场景与空间交互，React 负责产品页面和业务面板，通过受控状态桥连接。Phaser 不持有权威业务状态，完整世界状态以服务端为准。
D75后端框架使用 Fastify，并按 World、Simulation、Agent、Generation、Timeline、AI、Asset 划分领域模块。保留清晰模块边界，不引入重量级微服务。
D76主数据库使用 SQLite + WAL；生成资产保存在文件系统或对象存储，通过引用入库，并抽象 Repository。本地零数据库配置，同时为未来替换服务型数据库保留边界。
D77客户端通信REST 承载命令和查询，WebSocket 推送实时世界事件；事件携带 event_id、world_id、branch_id 与 world_version。断线后按游标补发缺口，缺口过大则下发新快照。
D78任务队列SQLite 持久任务表 + 进程内 Worker，记录状态、租约、重试、进度和幂等信息，并提供 JobQueue 接口。进程重启后任务可恢复；未来可替换 BullMQ 而不改领域调用方。
D79数据契约Drizzle 负责数据库 Schema、迁移和事务；Zod 负责领域、API、WebSocket、动作与 AI 输出校验。Repository 将数据库记录映射为领域对象，避免 ORM 结构泄露到接口层。
D80前端状态TanStack Query 管服务端查询与缓存，Zustand 管 WebSocket 实时投影和轻量 UI 状态。完整详情按需查询，客户端不复制一套完整世界权威状态。
D81工程目录采用 pnpm workspace 轻量 Monorepo：apps/web、apps/server、packages/shared，暂不引入 Turborepo。共享契约并保持构建链简单，适合 2–3 天实现和现场改码。
D82地图寻路权威逻辑地图使用网格与 A*；AI 图片仅作为视觉层，并为未来 NavMesh 预留接口。动态生成和扩建后仍可确定性校验碰撞、入口与全局可达性。
D83记忆检索SQLite FTS5 配合新近度、重要度与相关度综合评分；Embedding 检索只预留接口。MVP 不部署向量数据库，仍能解释每条记忆被召回的原因。
D84模型适配使用统一轻量 AIProvider，四类模型角色分别配置 baseURL、apiKey 和 model，优先兼容 OpenAI 风格接口。供应商可混用；密钥不入库，缺失或失败时切换 Mock。
D85参考边界Generative Agents 与 WorldX 文档用于校准设计，但 90/10 反脸谱化与戏剧性高光评分不纳入正式需求。不因参考项目继续扩大面试版本范围。
D86部署形态开发时前后端分端口；生产时由单个 Fastify 服务托管 React 静态文件、REST、WebSocket 与后台任务。线上仅一个访问地址；SQLite 与生成资产使用持久目录，并提供 Dockerfile。
D87账号范围仅实现账号密码登录，不做注册、邮箱验证、找回密码、OAuth 或账号绑定。世界、时间线与任务绑定 user_id，服务端强制进行所有权校验。
D88账号来源初始化数据提供演示账号，后台脚本可以创建账号，不开放用户自行注册。面试官可直接登录，同时避免公开注册带来的额外治理工作。
D89登录状态密码哈希保存；登录后使用签名 HttpOnly Cookie 保存用户 ID 与过期时间，不建立独立会话表。实现简单且可跨服务重启；不支持单次会话撤销和多设备管理。
D90日志范围结构化日志与完整监控平台不纳入需求，只保留必要的运行时与错误输出。不单独建设可观测性系统，AI 检查器仍负责展示产品内 AI 决策信息。
D91实现策略面试版本以核心纵向切片为优先，其他能力围绕主流程分级实现。首先保证 README 可跑通和端到端主流程稳定，而不是堆积浅层功能。
D92创建双轨内置世界保证稳定演示；一句话真实生成结构、NPC 和规则，图像失败时使用程序化或预生成资产。运行期扩建只保留接口与入口，不作为面试版稳定验收能力。
D93面试人口默认运行 5 名完整居民，所有居民能力相同；数据、生成器和调度面向约 20 名扩展。不以 20 名居民同时稳定运行作为首版验收条件。
D94室内深度所有主要建筑均生成可进入的程序化室内；两个核心室内具备重点美术和更丰富交互。其余室内仍需具备入口、碰撞、移动、功能标签和基础交互。
D95真实 AI 深度世界结构、NPC 决策和对话完整调用真实 AI；图像生成与视觉审查接通真实接口但允许缓存和降级。现场演示不能因绘图耗时或外部接口失败而阻塞。
D96面试持久化实现追加事件、周期与里程碑快照、刷新恢复和基础历史分支；世界包导入导出做到最小可用。复杂快照治理、资产回收和精细任务恢复不作为首版验收条件。
D97面试因果链玩家事件触发 NPC 感知、决策、行动和至少一级后续事件，节点保存父事件、依据和状态变化。可从最终结果反向追踪初始事件；平行对照只保留 branch_id 与接口。
D98调试工作台实现上下文与 Prompt 检查、临时编辑、沙盒重放和双模型或 AI/Mock 比较。重放默认不写回真实世界；不建设数据集、审批、批量评测等完整 LLMOps。
D99基础 CIGitHub Actions 自动执行 lint、类型检查、离线测试与生产构建，真实 AI 契约测试手动触发。默认 CI 不需要密钥、不访问模型服务，也不产生 AI 调用费用。
D100核心路由登录、首页/世界库、创建世界、小镇主界面、因果分析、AI 调试工作台共六个核心路由。NPC、对话、事件注入和设置收进主界面抽屉，不继续拆分后台页面。
D101文档组织README 聚焦快速启动和体验，docs/technical-design.md 记录完整技术方案与设计取舍。面试官可在 5 分钟内跑通，同时有独立材料深入评审。
D102启动方式同时提供 Docker 一键体验和 pnpm 本地开发，两者自动完成迁移、演示账号和内置世界初始化。Docker 保证环境一致，pnpm 支持现场修改和热更新。
D103线上地址公开 HTTPS 地址覆盖完整投递与面试周期，README 标注演示账号、有效期和冷启动提示。本地启动与录制视频作为双重替代方式。
D104演示视频制作约 5 分钟视频，覆盖自主行动、决策依据、对话、事件因果、Mock、恢复和调试工作台。边操作边讲解，保持一条连续且可复现的演示主线。
D105现场改码预留“新增动作工具”案例，贯通共享 Schema、合法性校验、执行器、Mock、UI 与测试。修改范围可控、效果可见，并能证明模块边界与全栈能力。
D106AI 修改案例记录 AI 初版物品转交逻辑的事务与幂等风险，以及人工校验、修正和补测试过程。突出候选人对 AI 代码进行工程审查，而不是直接接受生成结果。
D107个人决策账本按需求、架构、算法、实现与测试记录 AI 的参与方式、个人取舍、验证和推翻，并引用代码与测试。保持精简，不公开无关的完整 Prompt 或对话原文。
D108提交历史Git 按项目骨架、模拟、交互、AI/Mock、恢复、调试、测试与交付等可运行里程碑提交。关键提交尽量保持可构建，避免一次性提交或碎片噪声。
D109接口文档从 Fastify 路由 Schema 自动生成 OpenAPI，README 只保留登录与核心主流程调用示例。接口定义以代码为源，避免手写文档与实现漂移。
D110线上 AI 额度演示账号按能力限制真实 AI 调用次数，额度耗尽后自动 Mock，并复用安全缓存结果。面试官仍可验证真实接入，同时控制费用和公开滥用。
D111交付检查pnpm verify 自动执行密钥检查、lint、类型检查、离线测试、构建、迁移与种子冒烟，再人工走完整演示。以新环境和无密钥模式验证可交付性，不依赖作者机器的隐含状态。
D112演示世界内置世界采用现代滨河社区“栖溪镇”。现实日常语境无需额外解释，面试官可立即判断居民行为是否合理。
D113共同背景周末河岸市集正在筹备，作为居民相遇和资源流动的共同背景，但不预设剧情结果。平时仍有各自工作、休息和社交，不让所有行动只围绕市集。
D114关系结构5 名居民形成松散熟人网络，以社交、健康、物资、移动与信息节点互相连接。每人拥有独立目标，已有关系中同时存在信任、欠款、互助和轻微矛盾。
D115职业组合咖啡馆经营者兼协办人、社区医生、杂货店老板、配送员和社区记者。五种角色共同支持经济、健康、信息传播和空间移动的可见闭环。
D116林夏31 岁，外向热心、责任感强，压力下过度控制；筹办市集是为弥补上次失误并缓解经营压力。重视承诺，喜欢计划和早晨，厌恶临时失约。
D117沈知衡36 岁，理性谨慎、隐性共情，重视证据、健康与风险，真正需要时会主动承担。面对流言先核验，负责市集急救点，与林夏长期互信。
D118何建国55 岁，务实节俭、看重互惠与兑现，对浪费和赊欠敏感，嘴硬但会照顾熟客。负责物资供应，因上次活动取消对林夏信任下降。
D119周放27 岁，灵活乐观、行动优先，珍视自由与义气，经济压力下偶尔冒险接单。熟悉全镇路线，承担配送并连接非正式信息；欠杂货铺小额货款。
D120唐雨澄26 岁，观察敏锐、有公共责任感并渴望影响力，追问细节但警惕放大不确定信息。上次如实报道活动取消，与林夏保持礼貌但紧张。
D121演示地点河岸广场、咖啡馆、诊所、杂货铺、社区中心、公寓和滨河步道构成场景网络。咖啡馆和诊所为重点室内，其余主要建筑仍可进入并具备基础功能。
D122演示事件推荐注入“气象台发布暴雨预警，河岸场地可能封闭”，触发核验、风险评估、计划调整、库存与配送变化。系统只注入事实和影响范围，不写死每名居民的反应结果。
