# WorldX 生成管线审阅与栖溪镇改造方案(已落地)

> 状态:已审阅、已落地(规划中)一→ 结论随视觉管线提交。原则:学习编排方法,不复制提示词、资产或业务设定。

## 1. 实际审阅范围

对本机 WorldX 只读审阅:世界设计提示词与编排、地图生成/审查、可行走区与网格、人物精灵表生成与审查、一张实际地图与人物 spritesheet、项目理念文档。未复制其提示词、资产或代码。

## 2. 值得借鉴的机制(栖溪镇采用方式)

| 机制 | WorldX 做法 | 栖溪镇 |
| --- | --- | --- |
| 先设计后绘图 | 结构 JSON 先行 | WORLD 先产出并校验 `WorldBlueprint` 与 NPC,再美术 |
| 短地图提示 | 简单场景/风格/构图 | Prompt 只给场景、风格锁与蓝图约束 |
| 生成后审查 | VISION 反馈进下一轮 | 最多重试一次,再降级;Trace 留问题码 |
| 资产并行 | 地图/人物并发生成 | STRUCTURE 通过后并行 map/character 子任务 |
| 固定人物布局 | 统一动作表 | 自有 6×5 合同:左/前/后行走、待机、表情行 |

## 3. 我们刻意改变的地方(核心差异)

WorldX 会用遮罩/识图推导部分玩法几何,模型误判会悄悄改碰撞和入口。栖溪镇改用权威顺序:

```text
一句话设定 → WORLD 结构设计 → Schema/引用/连通性验证 → 权威 WorldBlueprint
  → 蓝图控制图 + PixelStyleSpec(创建时锁定)
  → IMAGE 地图与人物并行 → VISION 对照蓝图审查
  → 通过:登记资产;失败:反馈重试一次;再失败:预生成/程序化回退
```

关键不变量:① Blueprint 决定地点/入口/路径/碰撞/出生点,图片永不反向改写;② 资产绑定 `blueprintHash + styleSpecId` 防旧图误配;③ VISION 只返回有限问题码与自然语言反馈,不写库;④ 无 IMAGE/VISION Key 时结构世界仍立即可玩。
