# WorldX 生成管线审阅与栖溪镇改造方案

> 状态：已审阅，正在落地  
> 原则：学习编排方法，不复制提示词、资产或业务设定

## 1. 为什么当前画面不如 WorldX

此前栖溪镇使用 Phaser `Graphics` 绘制矩形建筑和圆形居民，它解决的是 Day 1 的实时状态投影，不是美术生成。Codex 在开发阶段可以读取图片，不代表运行中的 Web 项目已经配置了 IMAGE 与 VISION 模型；这是两个不同的执行环境和凭据边界。

本轮已经加入原创的栖溪镇预生成像素地图、程序化像素居民，以及 IMAGE/VISION 编排契约。未配置图像模型时仍显示预生成或程序化资产，不阻塞演示。

## 2. 实际审阅范围

对本机 WorldX 做了只读审阅，覆盖：

- 世界设计提示词与 `world-designer` 编排；
- 地图生成、地图审查、区域/元素定位、可行走区生成和网格计算；
- 人物精灵表生成与审查提示词；
- 一张实际生成地图和一张实际人物 spritesheet；
- 项目理念与内容创意文档。

没有复制 WorldX 的提示词文本、图片资产、角色设定或代码实现。

## 3. 值得借鉴的机制

| 机制 | WorldX 做法 | 栖溪镇采用方式 |
| --- | --- | --- |
| 先设计后绘图 | 世界设计先输出结构化 JSON | WORLD 先产生并校验 `WorldBlueprint` 与 NPC，再开始美术 |
| 短地图提示 | 地点、风格、构图保持简洁 | Prompt 只给场景、风格锁与蓝图约束，避免堆砌故事 |
| 生成后审查 | VISION 反馈进入下一次生成 | 最多重试一次，Trace 保存问题码与反馈，随后降级 |
| 区域定位 | 彩色覆盖图 + 程序提取边界 | 可作为注册辅助，但不允许覆盖 Blueprint 几何 |
| 可行走审查 | 生成可行走遮罩，再计算网格 | 蓝图直接生成碰撞网格；VISION 只检查入口与画面是否冲突 |
| 地图与人物并行 | 两种资产并发生成 | STRUCTURE 通过后并行启动 map 与 character 子任务 |
| 固定人物布局 | 统一多行多列动作表 | 自有 6×5 合同：左/前/后行走、正面待机、表情行 |

## 4. 我们刻意改变的地方

WorldX 的画面生成结果会通过遮罩和识图推导一部分玩法几何。它很灵活，但模型误判可能悄悄改变碰撞和入口。栖溪镇采用更适合面试解释和自动测试的权威顺序：

```text
一句话设定
  → WORLD 结构化设计
  → Schema / 引用 / 连通性验证
  → 权威 WorldBlueprint
  → 蓝图控制图 + 世界级 PixelStyleSpec
  → IMAGE 地图与人物并行生成
  → VISION 对照蓝图审查
  → 通过：登记资产；失败：反馈重试一次；再失败：预生成/程序化回退
```

关键不变量：

1. `WorldBlueprint` 决定地点、入口、路径、碰撞和出生点；图片永远不能反向改写它。
2. `PixelStyleSpec` 创建世界时锁定，地图与所有人物共用投影、像素尺度、光照和视觉语言。
3. VISION 返回有限问题码和自然语言反馈，不直接写数据库。
4. 每份资产绑定 `blueprintHash + styleSpecId`，防止旧图误配新几何。
5. 没有 IMAGE/VISION Key 时，结构世界仍立即可玩。

## 5. 自有提示词策略

### 地图生成

- 说明这是可玩的生活模拟地图，不是概念插画；
- 指定接近 90° 的俯视投影、清楚入口、连通道路、矩形建筑语言；
- 使用由 Blueprint 渲染出的控制图约束空间，而不是仅靠自然语言猜位置；
- 明确禁止人物、文字、UI、水印和等距透视；
- 重试只附加上一轮的审查问题，不重写世界设定。

### 地图审查

- 输入原图、蓝图控制图与关键入口清单；
- 只检查投影、布局、入口遮挡、路径连通、风格漂移和意外文字/人物；
- 结果必须是 `VisualReviewSchema`，分为 `pass/retry/fallback`；
- 审查分数用于调试展示，不参与碰撞计算。

### 人物生成

- 用结构化 Appearance Spec 描述稳定身份与职业特征；
- 固定 6×5 网格和每行语义，要求所有帧保持同一人物；
- 要求真实透明背景、完整不裁切、无文字和底板；
- 人物审查额外检查网格、透明通道、身份漂移和裁切。
